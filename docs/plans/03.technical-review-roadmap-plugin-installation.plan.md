# Technical review, roadmap, and plugin installation

## Objective

Record a per-file technical review of the CLI, Obsidian companion, tests,
build configuration, and related documentation; prioritize follow-up work;
and make `arc init` install the ARC Obsidian companion by default.

## Decisions

- Install `manifest.json`, `main.js`, and `styles.css` into
  `.obsidian/plugins/arc-obsidian-plugin/` during `arc init`.
- Use `arc init --no-plugin` to opt out. Dry runs preview plugin files too.
- Preserve existing plugin files individually; only missing files are created.
- Reject symlinked plugin parent directories so plugin files cannot be written
  outside the selected vault through a linked `.obsidian` path.
- Bundle the plugin as part of `pnpm build`, so packaged CLI installations
  have the assets required by `init`.
- `init` does not enable the plugin in Obsidian. Users must enable it in
  **Settings → Community plugins**. Dataview and Templater remain separate
  user-installed plugins.

## Implementation roadmap

### Phase 1: Install the companion with `arc init` — complete

- [x] Bundle the companion as part of `pnpm build`.
- [x] Install the packaged files by default and support `--no-plugin`.
- [x] Preserve existing plugin files and include them in dry-run reporting.
- [x] Reject symlinked plugin parent directories.
- [x] Add CLI, init, rollback, dry-run, and collision tests.
- [x] Align CLI, plugin, vault-structure, and build documentation.
- [x] Rename the original `00` plan to match the plan filename convention.

### Phase 2: Improve wikilink diagnostics — next

- [ ] Ignore wikilink-like text inside inline and fenced code without changing reported source offsets.
- [ ] Add regression tests for code spans and retain existing embed, alias, and heading behavior.
- [ ] Run the targeted plugin test suite and full typecheck.

### Phase 3: Validate in Obsidian — before release

- [ ] Build and install the plugin in a disposable Obsidian vault.
- [ ] Smoke-test status-bar reports, unresolved-link reports, and note creation.
- [ ] Confirm reload and upgrade behavior, including a vault with pre-existing plugin files.

### Phase 4: Reassess release and ecosystem work — deferred

- [ ] Decide whether to submit the plugin to the Obsidian community directory.
- [ ] Define a user-consented update path before adding any automatic plugin replacement.
- [ ] Keep AI-client synchronization, semantic linking, and lifecycle automation out of scope until separate requirements and safety boundaries are established.
