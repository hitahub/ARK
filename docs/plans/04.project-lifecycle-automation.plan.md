# Project lifecycle automation

## Status

Implemented as `arc archive <project-name> [path]`. This plan records the
requirements, safety decisions, and validation for the lifecycle command.

## Command contract

```bash
arc archive <project-name> [path] [--dry-run] [--yes]
```

- `project-name` is the exact name of a direct child folder in `200_Projects/`.
- The optional vault path defaults to the current working directory.
- The project must contain exactly one Markdown note with `type: project` and
  `status: done`.
- The project moves to `900_Archive/Projects/<project-name>/`; the project index
  status changes to `archived`.
- Interactive confirmation defaults to no. `--yes` confirms without prompting;
  non-interactive use without `--yes` fails with guidance. `--dry-run` previews
  the operation without prompting or writing.

## Safety and metadata

- Existing archive destinations are rejected and never overwritten.
- Symlinked project roots, symlinks or special files inside the project, and
  symlinked archive directories are rejected.
- Project files and note contents are preserved except for the project index's
  status field. Path-qualified links to the old folder are not rewritten;
  users should review those references after the move.
- The project is moved before its index is updated. If the atomic status write
  fails, ARC attempts to move the project back. Incomplete rollback is surfaced
  as an `AggregateError` with the original and rollback failures.
- Archived projects are outside `200_Projects/`, so the generated active
  project, task-note, and action-item Dataview queries exclude them.

## Validation

Tests cover successful moves, status and content preservation, dry-run and
decline paths, collisions, incomplete project metadata, invalid and missing
projects, symlink rejection, and rollback after a metadata write failure.
Documentation was updated across the CLI guide, vault structure and workflows,
metadata contract, architecture, development guide, and roadmap.
