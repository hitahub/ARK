# Saving link suggestion reports

## Status

Implemented in [issue #38](https://github.com/hitahub/arc/issues/38), following
[discussion #36](https://github.com/hitahub/arc/discussions/36). The optional
`--output` argument saves the deterministic report as a local Markdown
artifact without changing suggestion ranking or scanning scope.

## Objective

Let users keep, compare, or share a reviewable snapshot of link suggestions
while preserving the command's deterministic, offline, read-only treatment of
the selected vault.

## Proposed user-facing behavior

- The optional `--output <file>` argument to
  `arc links suggest <vault-path>` saves the Markdown report.
- Without `--output`, retain the current stdout output and behavior exactly.
- With `--output`, write the same human-readable report and retain the current
  stdout report. A successful write may additionally print a concise
  confirmation to stderr.
- Use Markdown for the first version. Include the note count, ranked candidate
  pairs, similarity scores, shared terms, and an explanation that matches are
  heuristic suggestions requiring manual review.
- Keep report content deterministic: do not include timestamps or machine-
  specific absolute vault paths.
- Require the output file not to exist and its parent directory to exist.
  Never replace an existing file, including through a symlink or a path that
  resolves to an existing file.
- Require the output destination to be outside the selected vault so the
  vault remains unchanged.
- Only write after the scan and ranking complete successfully. Report
  destination errors explicitly; do not silently fall back to stdout-only
  success when saving was requested.

The flag and Markdown format were discussed in
[Discussion #36](https://github.com/hitahub/arc/discussions/36).

## Requirements and safety constraints

- Preserve the current explicit vault selection, offline operation, lexical
  scoring, candidate ordering, and scan limits.
- Do not modify, create, or annotate anything inside the source vault.
- Do not send note contents, candidate data, or metadata to a remote service.
- Do not overwrite any output file or follow symlinks in the destination
  path. Reject special files and unsafe paths.
- Ensure failures do not leave a partial report at the requested destination;
  clean up any temporary output and surface cleanup failures.
- Keep the report bounded by the existing maximum of 20 candidates and the
  five displayed shared terms per candidate.
- Preserve stdout output when `--output` is omitted. Document and test the
  output-channel behavior when saving is requested.
- The report is a review aid, not a claim that two notes are meaningfully
  related. No suggested links are applied automatically.

## Out of scope

- JSON, HTML, or multiple report formats.
- Embeddings, model downloads, hosted inference, network access, or caching.
- Automatically creating or modifying wikilinks or note contents.
- Comparing reports, maintaining a report history, or automatically cleaning
  up saved reports.
- Changing the note scope, matching algorithm, thresholds, or scan budgets.

## Acceptance criteria

- `arc links suggest <vault-path>` remains behaviorally compatible and does
  not write files.
- `--output <file>` saves a deterministic Markdown rendering of the same
  suggestions that are printed to stdout.
- An empty result produces a clear, reviewable report.
- Existing destinations, unsafe paths, symlinks, and destinations within the
  vault are rejected without changing existing content.
- A scan or write failure is reported as an error and does not leave a
  partial destination file.
- Tests verify exact report content, deterministic output, default behavior,
  output path validation, overwrite protection, failure cleanup, and that
  source vault contents remain unchanged.
- User documentation describes the option, report contents, safety behavior,
  and manual-review limitation.

## Validation expectations

Run the repository checks:

```bash
pnpm format:check
pnpm test
pnpm typecheck
pnpm build
```

Add focused CLI tests for the exact saved report shape, output path edge
cases, write failures, and proof that source notes remain unchanged. Record
the exact commands and results in the implementation pull request.

## Pull requests and Conventional Commits

Pull request titles and non-merge commit subjects must follow the
CI-enforced Conventional Commits ruleset documented in
[Contributing](../../CONTRIBUTING.md):

```regex
^(build|chore|ci|docs|feat|fix|perf|refactor|revert|style|test){1}(\([\w\-\.]+\))?(!)?: ([\w ])+([\s\S]*)
```

Use a lowercase scope where relevant, followed by a colon and a space. For
example:

- `feat(links): save suggestion reports`
- `test(links): cover report output failures`
- `docs(links): document saved suggestions`

When opening a pull request, summarize the behavior and compatibility impact,
list checks with their results, and link the related discussion.
